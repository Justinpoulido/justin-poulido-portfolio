Process

How a build goes

  1. Write the spec

    I pin down the requirements first, including local rules such as TTD pricing and 12.5% VAT, so everyone agrees on what done means.

  2. Build in phases

    Work ships in stages that can each be reviewed. The RFQ system went out in five.

  3. Test before release

    Automated tests catch the defects that matter: thread safety, permissions, prices shown to the wrong role.

  4. Release and document

    I prepare the production release and leave documentation the next person can follow.
